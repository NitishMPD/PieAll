# PieAll
Author: Nitish

## Ring customization — 21 October 2026

The dashboard has a Customize ring section. Users pick the hold key (`, Caps Lock, Pause, Scroll Lock or F1–F12; Esc cancels capture) and edit the ring layout per context: Images, Files, Text, Windows, and any of the 57 app profiles. A layout is an ordered list of ring slices. Slices come from the context's built-in presets, their choices, plain registry actions of the matching groups, or that app's shortcuts. Users can reorder, remove, add and reset. Slices past eight move into More. A saved layout replaces the built-in one; keys that no longer exist are ignored; Reset restores the default. For an app, the saved layout replaces the six quick actions, while Search actions and Window tools stay fixed.

Preferences live in the WebView's `localStorage` (`pieall.prefs`), shared by the dashboard and ring windows, so a change reaches the ring on its next open. The dashboard sends the saved hold key to the native hook through `set_trigger_key` at startup and on change; the hook accepts only the keys listed above, and a quick tap still types the chosen key. Verification gap: the hook change builds under `cargo check` but has not been exercised on real keyboards, and `localStorage` sharing between the two windows has not been tested in WebView2.

## Contextual app shortcuts — 21 October 2026

App-specific Windows shortcuts are now in product scope. `src/shortcuts.json` supplies 3,079 app-scoped bindings across 57 profiles, alongside the existing 44 local tools (3,123 available bindings/tools across supported contexts). This counts bindings per app, including shared browser/editor defaults; it does not mean 3,079 distinct automation engines or new file transformations. Everyday coverage includes Explorer, Chromium/Firefox browsers, Word/Excel/PowerPoint/Outlook/OneNote, Notepad/Paint, Terminal, Slack/Discord/Teams, Spotify/VLC/Zoom, Notion/Obsidian and Acrobat. Specialist profiles include Figma, Photoshop, Illustrator, Premiere Pro, After Effects, Blender, GIMP, Krita, Inkscape, Audacity, Godot, VS Code derivatives and JetBrains IDEs.

`src/shortcuts.rs` owns immutable profile data, stable action IDs, key grammar, shared keymaps and lookup indexes. The native shell warms the catalog once at setup. Profiles select six quick actions shown directly for a window context. Search actions opens the dashboard's flat searchable Apps list; `/` from the ring provides the same route. App shortcuts never use category submenus or recursive More lists. File/image/text selections retain their selection tools instead of adding an app shortcut tree. The native session is the sole action source for the UI: unrelated apps are excluded, including stale or incorrectly eligible rows, and unsupported apps expose no shortcuts. The dashboard no longer fetches the full library or offers an All apps selector. Search indexes only the session subset, defers query results and renders at most 60 result buttons, with accessible pagination. Changing the captured app clears the previous query and page. Opening Search actions clears category/search state and focuses the search input; execution still targets the captured source window, never the foreground dashboard.

App identity comes from the foreground HWND/PID captured before PieAll appears, then the process executable basename read with limited query rights. Exact executable aliases select profiles; titles never identify websites or apps. Explorer's desktop windows do not get its folder-window shortcuts. Unrecognized executables retain existing file/text/window behavior. `capture_text` in each profile suppresses the Ctrl+C probe in creative/media/meeting tools and terminals, where copying may act on non-text content. Browser, document, chat and code selections retain existing text capture. Figma in a browser receives the browser profile; website-specific shortcut detection is not implemented.

Shortcut dispatch uses the existing native revision checks and one-operation lease, without starting a codec worker. IPC supplies only a bundled action ID and revision; custom parameters, key sequences and window/process overrides are rejected. Native code revalidates HWND/PID/executable and foreground focus before each chord. It waits up to five seconds for held keys/buttons to come up, cancels on focus change or new input between chords, marks injected events to bypass the hold hook, and releases injected keys after partial SendInput failure. Ctrl+backtick temporarily unregisters PieAll's global hotkey during dispatch so commands such as VS Code's terminal and Excel's formulas are not swallowed; restoration is attempted on both success and failure, with a visible error if it fails. Shortcut attempts invalidate the prior selection snapshot/revision. The toast says “Shortcut sent”; it cannot prove the target app performed the command. App shortcuts can change documents, clipboard, selection or app settings according to the target app; local file tools retain their source-preserving guarantees.

Bindings target Windows US keyboard defaults. App version, current tool/mode, dialogs, plugins, customized keymaps, alternate layouts and executable aliases can change behavior. Reference URLs are included for maintenance; every binding has not been exercised in its target app. No packages, network services, browser extensions or persistent configuration are added. Unit/static checks and search microbenchmarks do not establish native invocation latency, focus reliability, input delivery, frame rate or process-tree memory. Native acceptance remains user-run; see verification.md.

## Invocation model — 20 October 2026

PieAll is a tray utility, not an import app. The dashboard no longer opens at launch; it stays reachable from the tray as the full action list, the parameter editors and the accessible route.

- **Hold `** anywhere in Windows. A low-level keyboard hook (src-tauri/src/hold.rs) holds back each unmodified backtick press and opens the ring at the cursor on key-down, in every app. A release within 150 ms, or another key pressed first, counts as typing: the ring vanishes at once (no fade) and the backtick is replayed in order, so typing still works at the cost of a brief flash. Text capture (Ctrl+C) waits until the hold passes 150 ms, so a typed backtick never sends Ctrl+C, and a refused open (PieAll busy) is only reported once the hold is confirmed. Over apps whose shortcut profile never reads text (Figma, Explorer and the desktop, Adobe apps; terminals excluded because shells use ` as an escape), the hold is confirmed immediately and a plain ` is never typed there, like AutoHotPie. While held, the ring never takes focus: the app keeps it, shortcuts and results land without a focus round-trip, and the hook takes Escape to cancel. The ring is placed and sized with native calls only (no Tauri main-thread hops), and the release position is read natively. Once open, releasing the key always ends the ring: it runs the highlighted action slice (falling back to the cursor's direction when nothing is highlighted, e.g. after a flick past the rim), and anything else (center, nothing, a submenu slice, or a busy session) closes it. Submenus open only by resting 550 ms on their slice. As a backstop, the native side closes the ring itself 400 ms after the release (after any selection capture finishes) if it is still the same ring, so a stalled web round-trip or a failed run cannot leave it open. While ` is held, focus loss never closes the ring; otherwise only the ring that actually gained focus closes on focus loss (late focus-loss events from a hidden ring are ignored), and a ring that closed is never re-focused. Clicking a slice while still holding ` runs it; app shortcuts wait up to 5 s for the key to come up before sending. Shift (~), Ctrl, Alt, AltGr and Win combinations and injected input pass through. Ctrl+` and the tray open the same ring without the hold gesture. Pressing either again while the ring is open closes it.
- **Context comes from the foreground window**, captured before PieAll shows anything:
  - Explorer or the desktop: the selected items, read over COM. With Windows 11 tabs, only the active tab's visible view counts. With nothing selected, the open folder itself is the target.
  - Any other app except terminals: the selected text, copied with an injected Ctrl+C. The user's clipboard is snapshotted first (memory-backed formats, up to 64 MiB) and restored straight after; no clipboard change within 300 ms means no selection. Terminal classes never get Ctrl+C because it interrupts there.
  - Otherwise: that app's window (center, pin on top, fill screen, info).
- **Slices are presets that run in place, with no editors.** web/menus.ts defines them per context, and the native registry filters what's eligible. Empty submenus disappear, a single-choice submenu collapses into its choice, and anything past eight slices moves into More. Images: Compress 50%, Half size, Convert (PNG/JPG/WebP), Rotate (right, left, flip across, flip down), Copy image, Remove info, Make PDF, More. Files: Copy path, Zip, Extract here, Duplicate, Terminal here, Copy SHA-256, Folder size, Find duplicates, List/Test ZIP. Text: UPPERCASE, lowercase, Title Case, Trim, Sort, Unique lines, Format JSON, More (minify, URL and Base64 encode/decode, count).
- **Results stay where the user is.** File outputs publish beside the original under a smart name. Text results are pasted over the selection, then the user's clipboard is restored after 400 ms; if focus moved, the result stays on the clipboard and a toast says to press Ctrl+V. Reports (SHA-256, details, colors, folder size, duplicates, ZIP listing, window info, count) go to the clipboard. A small click-through toast window that never takes focus confirms each outcome where the ring was.
- **Smart names** (src/output.rs `output_stem`): `<stem>-<tag>.<ext>`, with tags compressed, rotated, flipped, clean, cropped, framed, grayscale, contact-sheet, or the new `<w>x<h>` after a resize. Re-applying the same tag replaces it instead of stacking it (photo-compressed (2) compressed again gives photo-compressed). Convert keeps the stem and changes the extension. Duplicate gives `<stem> - Copy`. Zip uses the item's name, or the folder's name for several items. Extract and Make PDF use the source stem. Collisions add Windows-style ` (2)` counters; nothing is ever replaced.
- **Image edits keep the source format** (JPEG re-encodes at quality 92). Compress writes JPEG at the chosen quality unless the image has real transparency, which stays as maximally compressed PNG. A compression that would not shrink the file saves nothing and says so. Resize accepts `scale` (1–100%) as well as maximum width/height.

Known limits: holding ` can no longer auto-repeat backticks; there is no setting yet to turn the hold gesture off or rebind it; text capture assumes the app's Ctrl+C/Ctrl+V; non-memory clipboard formats (GDI bitmaps, metafiles) are regenerated by Windows from their DIB/EMF siblings or lost; fullscreen games receive the ring like any app. Elevated windows ignore input from a non-elevated PieAll.

## Current architecture — 20 October 2026

PieAll now uses Tauri 2, React/TypeScript and its existing Rust execution core. The port stays in this repository; Captrain is an architecture reference and is unchanged. This section and docs/tauri-port.md supersede the historical baseline below. The original GDI shell is available only through the explicit legacy-ui feature; do not run both shells together.

Rust owns immutable contexts, revision/ticket rejection, source HWND/PID, registry eligibility, editor ownership, operation exclusion and results. The frontend cannot supply arbitrary file paths or override captured window identity. Native opening/dropping replaces context; clipboard text remains explicit. Worker dispatch precedes Tauri initialization. Existing output/ZIP guards, 120-second jobs, 1.2-second capture helper, one-job limit and 512 KiB results are retained. Previews are serialized off the UI thread, bounded to 64 MiB input/128 MiB allocation/16384-pixel dimensions, normalized for orientation and reduced to 320px.

The shell owns tray, fixed Ctrl+backtick invocation, foreground capture before focus, close-to-hide dashboard and single-instance forwarding of file arguments. Dashboard Show ring preserves explicit context. Exit/install refuse active operations or editors. Native focus, circular hit regions and mixed DPI remain acceptance gates.

The Cargo workspace defaults to pieall-desktop; one root Cargo.lock and one pnpm lockfile are used. Windows x64 NSIS packaging is per-user and uses system WebView2 instead of bundling a browser. Release Rust settings favor size. Smaller artifacts, lower process-tree memory and latency remain unmeasured goals.

The Tauri shell replaces the old custom updater protocol with Tauri signed updates. Configured releases check the PieAll GitHub feed after 10 seconds/every six hours; debug/unconfigured builds never check. Notes/progress, explicit download and separate install confirmation are implemented. Stable owned URLs, HTTPS, ten-minute/256 MiB download limits and installer/signed-version verification apply. Installer bytes remain bounded in memory until install/exit. Native operation leases exclude conflicting jobs/capture/editors. Versioning, signed installer/portable packaging, offline verification and draft-first CI are implemented in docs/releases.md. Keys, optional Authenticode and clean-Windows/live release validation remain external; Captrain's key is not reused. No analytics is implemented.

Formatting, TypeScript, static rendering and targeted tests are agent-run; builds/dev servers/app launches remain user-run. The workspace all-target Rust check and strict Clippy now pass; native installer/UI acceptance remains user-run. Do not infer native accessibility, focus, transparency, Explorer correctness, DPI or performance from source checks. The current UI uses SVG/local icons and alpha fills, with no native backdrop blur. Browser/engine/collection/configuration/cancellation/public-hub milestones remain outside the implemented slice.

See docs/tauri-port.md for architecture, signing and commands; verification.md for actual check results. Exact pre-port docs are preserved in docs/native-baseline-project.md and docs/native-baseline-design.md.

## Historical native baseline (legacy-ui only)

The following records the original implementation. Its no-network/GDI boundaries do not describe the default Tauri shell.

PieAll is a Windows 11 x64 local radial action utility. The full product vision remains in PieAll-plan.md. This first implementation prioritizes a real native invocation surface and working local image, file, ZIP, text and window tools. Browser integration, engines, collections and public publishing remain future milestones, not enabled actions.

## Runtime and ownership
The UI captures an explicit immutable selection before opening. Explicit dropped/opened files replace the prior context. Clipboard text requires an explicit user gesture. The registry owns all-target eligibility; handlers validate again. Expensive handlers execute in a temporary child process so codecs do not stay resident. Native UI owns presentation and source focus.

Outputs preserve original files, stage beside the destination and publish using atomic no-replace hard-link creation. Symlink/reparse inputs and destination parents are rejected; output names are controlled by the application. ZIP extraction uses a new private staging directory, validates paths, rejects links and applies quotas before publishing a new sibling folder. No existing directory is merged. Input byte/pixel/count limits protect workers. No network requests or analytics are implemented.

## First-slice boundaries
Native Win32 and opaque warm GDI rendering are a provisional implementation; Direct2D/translucency, full custom UI Automation, modifier-drag OLE support, automatic active-tab browser capture, persistent configuration/SQLite, cancellation and production packaging have not passed their planned gates. Explorer selection fails closed when foreground tab identity is ambiguous. Explicit file opening/dropping is the reliable fallback. No claims of measured performance or full 100-action coverage.

## Verification
Only formatting, type checks and targeted tests are permitted in this session. Builds, app launches and UI/runtime verification are user-run. Never infer native accessibility, focus, mixed-DPI correctness or latency from static checks.

## Implemented first-slice catalog
There are 44 implemented commands in the registry. Text formatting/case/encoding variants are separate commands, so this is not 44 distinct IDs from the 100-action product catalog. The exact current behavior, limits, run commands and remaining gates are in README.md and verification.md. Explorer capture runs in a disposable 1.2-second helper; jobs run in separate processes with a 120-second deadline and one job at a time. Results are capped at 512 KiB. Image previews normalize orientation and decode with allocation limits before creating a small thumbnail.
